example/refactored/example/Simple.java:
package example;

public class Simple {

    Simple() {
        throw new java.lang.Error();
    }

    void foo(String x) {
        throw new java.lang.Error();
    }

    void bar(Integer foo) {
        throw new java.lang.Error();
    }
}

run cmd: python3 run.py example --original example/original --refactored example/refactored

I thought that the differential tester would mark all three as divergent, since all refactored methods throw but the original ones do not. In my testing, the differential tester only compares one method--foo(String)--and outputs this as "Equivalent"; the other two are not compared at all.

I would also expect the constructor and bar(Integer) to also be tested, but it seems these are filtered out in the build_project step (in the call to auto_select#classify). This seems like it is due to two reasons: 1) constructors are discarded, and 2) non-primitive/String ([]) parameter types mean a method is excluded from testing.

At least according to Jazzer, reference parameter types are also supported (including those in the JDK but also in the target codebase), so I was wondering if there was a reason why these cases are not included, since they represent almost all of the methods I'm differentially testing in my project.
